## تحذيرات معلنة وليست مخفية

- `HardwareIds` مرة واحدة: `ANDROID_ID` مستخدم حاليًا في ربط ترخيص الجهاز، وليس معرف إعلان؛ يلزم مراجعة سياسة الخصوصية وتوافق تحديث الهوية/التوقيع.
- `DataExtractionRules` مرة واحدة: قواعد Android 12+ صريحة؛ `allowBackup=false` موجود، لكن lint يوصي أيضًا بتصريح legacy `fullBackupContent` للإصدارات الأقدم.
- `ObsoleteSdkInt` أربع مرات: شروط توافق API26 زائدة مع الحد الأدنى الحالي، لا تسبب فشل بناء.
- `UseKtx` ثلاث مرات: توصيات استخدام امتدادات Kotlin بدل APIs المكافئة.
- تحذيرات Kotlin من `AccessibilityNodeInfo.recycle()` المهجورة في الأنظمة الجديدة؛ تُحافظ الاستدعاءات على تحرير عقد الأنظمة الأقدم. لا يشكل نجاح lint ضمانًا لاختبارات تشغيل الأجهزة.

## ما لا تثبته النتائج

1. ملف APK debug الناتج بلا إعدادات Supabase حقيقية؛ يصلح لفحص تثبيت/واجهة أولي، ولا يعمل دخوله الحي حتى إنتاج نسخة مهيأة.
2. توقيع release **اختباري** مؤقت أُزيل بعد التحقق. ليس إثباتًا لهوية توقيع الإنتاج أو صلاحية تحديث تطبيق مثبت.
3. الاختبارات SQL محلية على أدوار Auth محاكية؛ لا تثبت تهيئة RLS/Auth للمشروع الحقيقي.
4. اختبارات Node تشمل تحققًا ساكنًا وبعض الدوال، لا تغطي كل العمليات الإدارية مع بيانات حقيقية.
5. لا تُدّعى تغطية اختبار شاملة أو فحص اختراق أو خلو كل التبعيات من الثغرات. بصمة Wrapper مثبتة، لكن metadata checksums لجميع التبعيات غير مضافة بعد.
6. لم تُغيّر صلاحيات GitHub أو أسراره أو إعدادات حماية فروعه/بيئة production. محاولة حصر أسماء الأسرار لم تسمح بها صلاحية التكامل (403)، ولم تُحاول تجاوزها.
