# بوابات الجاهزية الإنتاجية — سبّاق

هذه قائمة اعتماد تشغيلية، وليست تصريحًا بأن التطبيق اجتاز الاختبارات على أجهزة حقيقية أو أنه نُشر.

## 1. عقد الأمان والتفعيل

- حساب السائق يبدأ `pending`؛ لا تستطيع metadata التسجيل منح `active` أو دور مدير.
- `license_status` و`redeem_code` يلزمان جلسة Auth ومعرّف جهاز صحيحًا. تغيير الجهاز يخضع للـRPC الإداري وليس لتعديل محلي.
- يتيح التطبيق إدخال كود للحساب المعلّق أو المنتهي، لكنه لا يبدأ الالتقاط حتى إعادة التحقق من الترخيص.
- صلاحية الالتقاط محلية مؤقتة في ذاكرة العملية، تستند إلى وقت الخادم ومدة الاشتراك وساعة رتيبة. إعادة المصادقة/الخروج/موت العملية تلغيها.
- تُراجع صلاحية الترخيص دوريًا أثناء تشغيل الخدمة؛ تعطّل القراءة والتنفيذ عند انتهاء الصلاحية المحلية. الانقطاع لا يعني استمرارًا غير محدود.
- لا يُنفذ النقر دون موافقة المستخدم وإمكانية الوصول والإشعارات ومرشحات صالحة. يوجد إيقاف من التطبيق والإشعار.
- `admin_session_status()` تحقق إداري بلا كتابة؛ جميع العمليات الإدارية الحساسة تعتمد `require_admin()` وRLS خادميًا.

## 2. التحقق الآلي

```bash
./gradlew --no-daemon :core:test :app:testDebugUnitTest :app:lint :app:assembleDebug
node --test admin/tests/admin-static.test.mjs
```

في PostgreSQL محلي **معزول** فقط: نفّذ `supabase/tests/bootstrap.sql` ثم الترحيلات بالترتيب، ثم `license_test.sql` و`registration_admin_test.sql`. لا تنفذ bootstrap أو fixtures على الإنتاج؛ فهي تنشئ أدوارًا وحسابات اختبار.

- اختبارات PR لا تحصل على أسرار الإصدار.
- فرع الإصدار يجب أن يكون `main` أو `master` ومحميًا، وتستعمل مهمة الإصدار بيئة `production`.
- فحص تبعيات GitHub في هذا المستودع الخاص اختياري تشغيليًا: ضع متغير المستودع `ENABLE_DEPENDENCY_REVIEW=true` فقط بعد التأكد من توفر GitHub Code Security. عدم تفعيله لا يعني إجراء فحص ثغرات للاعتماديات.
- بصمة Wrapper مثبتة. أي metadata إضافية للتحقق من الاعتماديات تُراجع قبل اعتمادها؛ توليد checksums من مستودعات Maven لا يثبت وحده خلو الحزم من الثغرات.

## 3. نشر قاعدة البيانات

1. نسخة احتياطية واستعادة تجريبية من البيئة المطلوبة، ومراجعة مالك الدوال والصلاحيات.
2. طبق الترحيلات غير المنفذة بالترتيب: `0001` ثم `0002` ثم `0003`. لا تعِد تنفيذ fixtures على المشروع الحي.
3. `0003` ينشئ ملف السائق عند تسجيل Auth جديد يحمل `data.full_name` و`data.phone` صالحين. لا يعالج الحسابات السابقة بأثر رجعي؛ أكمل ملفاتها عبر مسار تسجيل معتمد أو إجراء إداري موثق.
4. تحقق من grants لكل RPC ومن RLS، ومن عدم إتاحة `require_admin` و`config_int` وtrigger للجمهور.
5. اختبر تأكيد البريد/بدونه، وسياسة كلمة المرور في Supabase، ورسائل الأخطاء، وقوالب البريد/روابط العودة قبل فتح التسجيل.
6. اختبر فشل المحاولات، حد الاسترداد، الكود المستخدم/الملغى، جهازًا آخر، الاشتراك المنتهي، والحساب المحظور.
7. راقب حجم `audit_log` و`redeem_failures` وحدد سياسة احتفاظ تشغيلية ونسخًا احتياطيًا؛ لا تحذف بيانات حية آليًا بلا اعتماد.

## 4. اختبارات القبول على الأجهزة

نفّذ وسجّل الجهاز وإصدار النظام وإصدار التطبيق المستهدف والنتيجة. الحد الأدنى Android 8/API26؛ اختبر خصوصًا Android 13 و14 و16.

| المسار | النتيجة المطلوبة |
|---|---|
| تسجيل صحيح وبريد يحتاج تأكيدًا | رسالة واضحة، حساب بلا صلاحيات زائدة، ثم دخول بعد التأكيد |
| pending / expired مع كود صحيح | يظهر التفعيل؛ تُراجع الرخصة قبل دخول لوحة السائق |
| كود خاطئ/مستخدم/ملغى ومعدل محاولات | رفض واضح بلا تشغيل |
| منع/سحب الإشعارات أو الإتاحة | لا يبدأ الالتقاط أو يتوقف؛ لا تستمر حالة تشغيل مضللة |
| موافقة التشغيل/إلغاؤها | الإلغاء لا يشغل الخدمة؛ التشغيل يظهر إشعارًا |
| خروج/قتل العملية/إقلاع | إيقاف الالتقاط وإلزام مصادقة جديدة |
| ترخيص ينتهي أثناء التشغيل | لا إيماءة بعد انتهاء lease؛ تتوقف الخدمة |
| انقطاع الإنترنت | لا يتجاوز العمل مهلة الترخيص المؤقتة أو انتهاء الاشتراك |
| وقت الجهاز يتغير | صلاحية lease لا تمتد بتغيير ساعة الحائط |
| شاشة تأكيد الرحلة/حزمة أخرى/زر غير قابل للنقر | لا قبول ولا إيماءة |
| شاشة كبيرة أو شجرة عقد مفرطة | رفض آمن دون تعليق التطبيق أو رفع محتوى الشاشة |
| مرشحات فارغة/معيبة/حد أدنى أكبر من أقصى | لا تشغيل/لا قبول |
| اتجاه RTL ولوحة مفاتيح وشاشة صغيرة | الحقول والأزرار قابلة للوصول، وكلمة المرور مخفية |
| إيقاف من الإشعار | إلغاء التفعيل والخدمة مباشرة |

## 5. لوحة الإدارة

- جلسة الويب ذاكرية، وتنتهي بعد خمول 15 دقيقة. يُطلب دخول لوحة الويب مستقلًا عن المصادقة الأصلية؛ لا يُمرر token من Android إلى JavaScript.
- اختبر مديرًا وغير مدير، انتهاء الجلسة، الخروج، XSS ضمن أسماء/ملاحظات، pagination، CSV injection، وفشل الشبكة.
- الاستضافة العامة ترسل CSP كـHTTP header وHSTS و`X-Content-Type-Options: nosniff` و`frame-ancestors 'none'`؛ قيّد `connect-src` بمضيف مشروعك المحدد. سياسة meta الحالية ليست بديلًا لكل رؤوس الاستضافة.
- التصدير الحالي يتوقف بأمان إذا تعذر إثبات الاكتمال أو تجاوز 1000 صف. الدفعات الأكبر تحتاج واجهة خادمية مدققة وليس إزالة الحدود.
- اختبر تنزيل CSV داخل Android WebView أيضًا؛ نجاحه في متصفح خارجي لا يثبت دعمه على كل WebView.

## 6. التوقيع والمتجر

- لا تستخدم مفتاح التوقيع القديم المكشوف في تاريخ المستودع. لا تُولّد أو تدوّر هوية توقيع الإنتاج بلا اعتماد المالك وتوافق تحديثات الأجهزة/Play App Signing.
- مفاتيح الاختبار المحلية أو APK debug لا تُستخدم للتوزيع الإنتاجي.
- افتح ملف APK الناتج وفحص توقيعه واسم الحزمة ورقم النسخة وminification على المسار النهائي نفسه قبل الإطلاق.
- اختبر تحديث نسخة مثبتة ببيانات حقيقية تجريبية وrollback قبل التوزيع.
- أكمل إقرارات خدمات الإتاحة وforeground `specialUse` وسياسة الخصوصية وData Safety في Play Console وفق الوظائف الفعلية. القبول يخضع لسياسات المتجر، ولا يضمنه البناء.
- راجع شروط منصات الرحلات والتفويض باستخدام الأتمتة. لا تنفذ عمليات تجريبية على عروض حقيقية دون بيئة وتفويض مناسبين.

## 7. التشغيل والرجوع

- عيّن مسؤول اعتماد الإصدار والمراقبة والنسخ الاحتياطي. مراقبة الأعطال والأداء ومقاييس تشغيل مُجهّلة تتطلب اختيارًا صريحًا للخدمة ومراجعة الخصوصية؛ لا توجد خدمة رصد حية مفعّلة بهذا التعديل.
- قبل SQL: احفظ نسخة احتياطية؛ الترحيلات أمنية، لذلك الرجوع الأعمى إلى سياسات `0001` يعيد ثغرات. عالج العطل بترحيل تصحيحي أو استعادة معتمدة.
- قبل Android: احفظ artifact وبصمته ونسخة الشيفرة، واحتفظ بهوية التوقيع خارج Git.
- قبل أي إطلاق: لا توجد أخطاء بناء/lint مفتوحة، الاختبارات موثقة، الترحيلات مطبقة، الاختبارات الحية/الأجهزة ناجحة، ومتطلبات المتجر والتوقيع معتمدة.
